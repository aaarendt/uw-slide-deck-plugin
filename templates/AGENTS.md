# [Presentation Name]

Built with the `uw-slides` plugin (version in `.uw-slides.json`).

**Plugin location.** Use the first of these that contains `tools/deckparse.py`: `$UW_SLIDES_HOME` if that variable is set; the directory where your client installed the `uw-slides` plugin (two levels above any of its `skills/<skill>/SKILL.md` files); or `~/.claude/plugins/local/uw-slides`. If none does, ask the user where the plugin is. Before writing any slide HTML, read from the plugin:
- `<plugin>/CLAUDE.md` — architecture, build workflow, skill list
- `<plugin>/design-systems/[BRAND]-brand/DESIGN.md` — colors, type, spacing, patterns
- `<plugin>/references/accessibility-requirements.md`
- `<plugin>/references/slide-schema.md` — `deck.yml` and `slides/<id>.md` format, generation rules
- `<plugin>/references/layouts.md` — the layout library

**deckparse.py.** This deck ships a vendored copy at `tools/deckparse.py`. Run all deckparse commands from the deck directory as `python3 tools/deckparse.py ...` (no variable expansion). The recommended allow rule is `Bash(python3 tools/deckparse.py *)`.

## Source of truth

- `deck.yml` holds the slide order; `slides/<id>.md` holds each slide's content. Edit these, not the HTML.
- `content/<id>.html` is generated by `/uw-slides:generate-slides`. Never hand-edit it unless the brief has `locked: true`.
- Never overwrite a locked slide. Ask before regenerating a slide whose brief changed.
- `OUTLINE.md` is generated (`./outline.sh`); never edit it.

## After every edit batch

```
/uw-slides:generate-slides
/uw-slides:design-review
/uw-slides:accessibility-check
```

## Build

```bash
./outline.sh            # OUTLINE.md (read-only overview)
./build.sh              # pass 1 → build/index.html
./build-visuals.sh      # pass 2 → build/index-with-visuals.html
./publish.sh            # pass 3 → build/index-published.html (self-contained)
```
